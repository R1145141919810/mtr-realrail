# 02 · 核心代码实现

完整项目位于工作区 `src/`（Architectury common/fabric/forge 三模块结构）。首次构建前需按文档 03 执行 `setupLibrary` 获取 MTR dev jar（编译依赖 `org.mtr.core`）。本文给出关键逻辑的完整代码、注入点说明与源码依据；所有注入目标已对照发行版 4.0.2–4.0.5 内嵌 TSC 源码（commit `599d1076`，该 jar 自 2025-10-14 起被 4.0.2~4.0.5 复用）逐行核对，机器编译验证步骤见文档 03/04。最低支持版本为 MTR 4.0.0 正式版（beta 系列无 `simulateMoving`/`getUpcomingSlowerSpeed`，见文档 04）。

## 2. 需求一：限速变更时机后移（含按节点切换）

### 2.1 原版行为（源码依据）

MTR 4.0.x（TSC，发行版 4.0.5 对应 commit `ce3a5090`）中列车是 `org.mtr.core.data.Vehicle`，位置为沿整条路径的一维距离 `railProgress`（指向行驶方向最前端），路径为 `vehicleExtraData.immutablePath`（`PathData` 列表）。每 tick 在 `Vehicle.simulateMoving` 中：

```java
// 原版：立即按"车头所在段"限速变速
speedTarget = vehicleExtraData.immutablePath.get(currentIndex).getSpeedLimitMetersPerMillisecond() * deviationSpeedAdjustment;
// 原版：预制动（对前方更慢的段提前减速）
final double upcomingSlowerSpeed = Siding.getUpcomingSlowerSpeed(vehicleExtraData.immutablePath, currentIndex, railProgress, speed, vehicleExtraData.getDeceleration());
```

`currentIndex` 由 `Utilities.getIndexFromConditionalList(immutablePath, railProgress)` 求出——车头一进入新轨道段（越过轨道连接器），该段限速立即生效。这就是任务书描述的问题点。

### 2.2 实现：边界状态机 + 车尾感知

核心逻辑集中在 `SpeedLimitHelper`（纯函数 + 每车状态，全部在服务端 tick 中调用）：

```java
package mtr.realrail;

import it.unimi.dsi.fastutil.objects.ObjectList;
import org.mtr.core.data.PathData;
import org.mtr.core.data.Position;
import org.mtr.core.tool.Utilities;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public final class SpeedLimitHelper {

	public static final class VehicleSpeedState {
		public int lastHeadIndex = -1;      // 上一 tick 车头所在段索引
		public int pendingTailBoundary = -1; // 待生效的 TAIL 边界所在段索引；-1 = 无
	}

	private static final Map<Long, VehicleSpeedState> STATES = new ConcurrentHashMap<>();

	private SpeedLimitHelper() {
	}

	public static VehicleSpeedState getState(long vehicleId) {
		return STATES.computeIfAbsent(vehicleId, key -> new VehicleSpeedState());
	}

	/** 每 tick 由 VehicleSimulateMixin 在 simulate() 开头调用。 */
	public static void updateState(long vehicleId, ObjectList<PathData> path, double railProgress, double totalVehicleLength, int headIndex) {
		if (headIndex < 0) {
			return;
		}
		final VehicleSpeedState state = getState(vehicleId);

		if (state.lastHeadIndex >= 0 && headIndex != state.lastHeadIndex) {
			if (headIndex > state.lastHeadIndex) {
				// 车头跨越轨道连接器进入段 headIndex；边界节点 = 该段起点（getOrderedPosition1 即行驶方向起点）
				final PathData enteredPathData = Utilities.getElement(path, headIndex);
				final Position boundary = enteredPathData == null ? null : enteredPathData.getOrderedPosition1();
				// 节点判定：TAIL → 延迟变更；HEAD → 立即变更（清除 pending）
				state.pendingTailBoundary = boundary != null && NodeModeStore.isTailMode(boundary) ? headIndex : -1;
			} else {
				state.pendingTailBoundary = -1; // 防御：索引回退时丢弃状态
			}
		}
		state.lastHeadIndex = headIndex;

		// 车尾完全通过边界（车尾所在段 ≥ 边界段）后，延迟变更生效
		if (state.pendingTailBoundary >= 0) {
			final double tailProgress = railProgress - totalVehicleLength;
			final int tailIndex = Utilities.getIndexFromConditionalList(path, tailProgress);
			if (tailIndex >= state.pendingTailBoundary) {
				state.pendingTailBoundary = -1;
			}
		}
	}

	/** 生效限速：有 pending 时保持边界前一段（旧段）的限速，否则用当前段限速。 */
	public static double getEffectiveSpeedLimit(long vehicleId, ObjectList<PathData> path, PathData headPathData) {
		final VehicleSpeedState state = STATES.get(vehicleId);
		if (state != null && state.pendingTailBoundary > 0) {
			final PathData previousPathData = Utilities.getElement(path, state.pendingTailBoundary - 1);
			if (previousPathData != null) {
				return previousPathData.getSpeedLimitMetersPerMillisecond();
			}
		}
		return headPathData.getSpeedLimitMetersPerMillisecond();
	}

	/** 车尾感知的预制动：遇到下一个 TAIL 判定节点即停止向前扫描（该节点前不预减速）。 */
	public static double getUpcomingSlowerSpeed(long vehicleId, ObjectList<PathData> path, int currentIndex, double railProgress, double currentSpeed, double deceleration) {
		final double stoppingDistance = 0.5 * currentSpeed * currentSpeed / deceleration;
		int index = currentIndex + 1;
		double railSpeed = -1;
		double bestDistance = 0;

		while (true) {
			final PathData pathData = Utilities.getElement(path, index);
			if (pathData == null) {
				return -1;
			}
			if (index > currentIndex && NodeModeStore.isTailMode(pathData.getOrderedPosition1())) {
				return railSpeed; // TAIL 节点后方的限速须等车尾通过才生效，不可预制动
			}
			final double newRailSpeed = pathData.getSpeedLimitMetersPerMillisecond();
			final double distance = pathData.getStartDistance() - railProgress;
			if (newRailSpeed < currentSpeed && distance >= bestDistance && distance <= 0.5 * (currentSpeed * currentSpeed - newRailSpeed * newRailSpeed) / deceleration) {
				railSpeed = newRailSpeed;
				bestDistance = distance;
			}
			if (pathData.getEndDistance() >= railProgress + stoppingDistance) {
				return railSpeed;
			}
			index++;
		}
	}
}
```

**语义（逐场景）**：

| 场景 | 行为 |
|---|---|
| 全部节点默认 TAIL（原需求） | 车头进入新段 → 限速不变；车尾完全通过连接器 → 立即按新段限速变速 |
| 节点设为 HEAD | 该节点恢复原版行为（车头进入立即变速） |
| 混合：B1(TAIL)→B2(HEAD) | 车头过 B2 时 pending 被清除，立即按 B2 后段限速变速（旧的延迟项不复活旧限速） |
| 安全制动 | stoppingPoint 分支（信号红灯/平台/前方占用）完全不受影响，仍会立即减速停车 |

### 2.3 注入点（VehicleSimulateMixin）

```java
@Mixin(Vehicle.class)
public abstract class VehicleSimulateMixin {

	@Shadow
	public final VehicleExtraData vehicleExtraData = null;

	@Shadow
	private double railProgress;

	@Shadow
	private long id;

	@Shadow
	private TransportMode transportMode;

	@Inject(method = "simulate", at = @At("HEAD"))
	private void mtrrealrail$onSimulateHead(long millisElapsed, ObjectArrayList vehiclePositions, Long2LongAVLTreeMap vehicleTimesAlongRoute, CallbackInfo ci) {
		if (vehicleExtraData == null || vehicleExtraData.immutablePath == null || vehicleExtraData.immutablePath.isEmpty()) {
			return;
		}
		final ObjectList<PathData> path = vehicleExtraData.immutablePath;
		final int headIndex = Utilities.getIndexFromConditionalList(path, railProgress);

		// 需求一：边界跨越检测 + 车尾通过判定
		SpeedLimitHelper.updateState(id, path, railProgress, vehicleExtraData.getTotalVehicleLength(), headIndex);

		// 需求二：登记列车当前所属信号系统（车身覆盖各段 signalColors 的并集）
		if (transportMode != null && !transportMode.continuousMovement) {
			final IntAVLTreeSet colors = new IntAVLTreeSet();
			final double tailProgress = railProgress - vehicleExtraData.getTotalVehicleLength();
			int tailIndex = Utilities.getIndexFromConditionalList(path, tailProgress);
			if (tailIndex < 0) {
				tailIndex = 0;
			}
			final int endIndex = Math.max(headIndex, 0);
			for (int i = tailIndex; i <= endIndex && i < path.size(); i++) {
				final PathData pathData = Utilities.getElement(path, i);
				if (pathData != null) {
					colors.addAll(pathData.getSignalColors());
				}
			}
			SignalIsolationRegistry.update(id, colors);
		}
	}

	/** 车头段限速 → 车尾/节点模式感知的生效限速 */
	@Redirect(method = "simulateMoving", at = @At(value = "INVOKE", target = "Lorg/mtr/core/data/PathData;getSpeedLimitMetersPerMillisecond()D"))
	private double mtrrealrail$getEffectiveSpeedLimit(PathData pathData) {
		return SpeedLimitHelper.getEffectiveSpeedLimit(id, vehicleExtraData.immutablePath, pathData);
	}

	/** 原版预制动 → 车尾感知预制动 */
	@Redirect(method = "simulateMoving", at = @At(value = "INVOKE", target = "Lorg/mtr/core/data/Siding;getUpcomingSlowerSpeed(Lit/unimi/dsi/fastutil/objects/ObjectList;IDD)D"))
	private double mtrrealrail$getUpcomingSlowerSpeed(ObjectList<PathData> path, int currentIndex, double checkRailProgress, double currentSpeed, double deceleration) {
		return SpeedLimitHelper.getUpcomingSlowerSpeed(id, path, currentIndex, checkRailProgress, currentSpeed, deceleration);
	}
}
```

**注入点源码依据**（TSC commit `599d1076` = 发行版 4.0.2–4.0.5 内嵌版本，已逐行核对）：

- `Vehicle.simulate(long, ObjectArrayList, Long2LongAVLTreeMap)` —— 每 tick 由 `Siding.simulateTrain` 调用（注意：发行版第三参数是 `Long2LongAVLTreeMap`；TSC master 已改为 `Long2ObjectOpenHashMap`，勿按 master 编写）；
- `Vehicle.simulateMoving` 中唯一的 `PathData.getSpeedLimitMetersPerMillisecond()` 调用与唯一的 `Siding.getUpcomingSlowerSpeed(...)` 调用（ATO 分支）；
- `vehicleExtraData` 为 `public final` 字段（以 `(Vehicle)(Object)this` 直接访问）；`railProgress`/`id`/`transportMode` 为生成的 Schema 中 `protected` 字段，以 `@Shadow` 访问（对任意可见性有效）。

## 3. 需求二：多信号系统隔离

### 3.1 原版行为（源码依据）

`Rail`（TSC `ce3a5090`）以四张 `Long2LongAVLTreeMap`（**颜色 → vehicleId**）维护预留状态，DFS 预留本身已按颜色递归：

```java
boolean isBlocked(long vehicleId, BlockReservation blockReservation) {
	if (signalColors.isEmpty() || isNotBlocked(preBlockedVehicleIds, vehicleId) && ... ) {
		if (blockReservation != BlockReservation.DO_NOT_RESERVE) {
			signalColors.forEach(color -> reserveRail(vehicleId, color, new ObjectOpenHashSet<>(), this, ...)); // 预留全部颜色！
		}
		return false;
	} else {
		return true; // 任一颜色被其他车预留 → 拦停
	}
}
```

**干扰点（与任务书前提一致）**：`isNotBlocked` 检查四张 map 的**所有**值、`forEach` 预留**全部**颜色——系统 A 的列车占用带 A+B 双色连接器的轨道时，会把 B 系统区间也标记占用；系统 B 的列车也会被 A 系统的占线拦停。

### 3.2 实现：按"列车实际所在信号系统"过滤

第一步（注册）：`VehicleSimulateMixin` 每 tick 将车身覆盖各轨道段 `signalColors` 的并集写入 `SignalIsolationRegistry`（TTL 10s，列车消失后自动失效，过期/未注册回退原版逻辑）。

第二步（隔离）：`RailSignalIsolationMixin` 重写 `isBlocked` 的颜色处理：

```java
@Mixin(Rail.class)
public abstract class RailSignalIsolationMixin {

	@Shadow private final Long2LongAVLTreeMap preBlockedVehicleIds = null;
	@Shadow private final Long2LongAVLTreeMap currentlyBlockedVehicleIds = null;
	@Shadow private final Long2LongAVLTreeMap preBlockedVehicleIdsOld = null;
	@Shadow private final Long2LongAVLTreeMap currentlyBlockedVehicleIdsOld = null;

	@Shadow
	private static void reserveRail(long vehicleId, long color, ObjectOpenHashSet<Rail> visitedRails, Rail rail, boolean currentlyBlocked) {
		throw new AssertionError("mixin shadow");
	}

	@Inject(method = "isBlocked", at = @At("HEAD"), cancellable = true)
	private void mtrrealrail$isBlocked(long vehicleId, Rail.BlockReservation blockReservation, CallbackInfoReturnable<Boolean> cir) {
		if (!RealRailConfig.INSTANCE.signalIsolation) {
			return; // 配置关闭 → 原版逻辑
		}
		final IntAVLTreeSet effectiveColors = SignalIsolationRegistry.get(vehicleId);
		if (effectiveColors == null) {
			return; // 列车未登记（首 tick/异常）→ 原版逻辑兜底
		}
		final boolean blocked = mtrrealrail$isBlockedByAnyColor(effectiveColors, vehicleId);
		if (!blocked && blockReservation != Rail.BlockReservation.DO_NOT_RESERVE) {
			final boolean currentlyBlocked = blockReservation == Rail.BlockReservation.CURRENTLY_RESERVE;
			final Rail self = (Rail) (Object) this;
			for (final int color : effectiveColors) {
				reserveRail(vehicleId, color, new ObjectOpenHashSet<>(), self, currentlyBlocked); // 只预留所属颜色
			}
		}
		cir.setReturnValue(blocked);
		cir.cancel();
	}

	private boolean mtrrealrail$isBlockedByAnyColor(IntAVLTreeSet colors, long vehicleId) {
		for (final int color : colors) {
			if (mtrrealrail$isBlockedBy(preBlockedVehicleIds.getOrDefault(color, 0L), vehicleId)
					|| mtrrealrail$isBlockedBy(currentlyBlockedVehicleIds.getOrDefault(color, 0L), vehicleId)
					|| mtrrealrail$isBlockedBy(preBlockedVehicleIdsOld.getOrDefault(color, 0L), vehicleId)
					|| mtrrealrail$isBlockedBy(currentlyBlockedVehicleIdsOld.getOrDefault(color, 0L), vehicleId)) {
				return true;
			}
		}
		return false;
	}

	private static boolean mtrrealrail$isBlockedBy(long blockedVehicleId, long vehicleId) {
		return blockedVehicleId != 0 && blockedVehicleId != vehicleId;
	}
}
```

**语义**：

| 情况 | 行为 |
|---|---|
| 列车已注册、所属颜色集非空 | 只检查/预留所属颜色 → 各系统独立，互不干扰（任务书需求二） |
| 列车已注册、颜色集为空（车在不带信号的轨道上） | 不受任何信号约束、不预留任何区间（"不属于任何系统"） |
| 未注册/过期 | 回退原版全颜色逻辑（安全兜底） |
| `signalIsolation=false` | 完全原版行为 |

**不改变的部分**：物理防撞（`Vehicle.railBlockedDistance` 中 `VehiclePosition.getClosestOverlap` 重叠检测）与颜色无关，列车之间仍然不会相撞；信号灯的渲染数据流（`Rail.tick1 → SignalBlockUpdate → 客户端 railIdToCurrentlyBlockedSignalColors`）按颜色打包，隔离后的状态自动正确显示。

## 4. 按节点切换判定方式：在 MTR 原版界面中追加按钮

**需求**：刷子右击轨道节点时必须**先打开 MTR 原版界面**（轨道形状 / 轨道样式，原版功能不变），
在该界面里通过一个独立按钮跳转到"节点限速判定"界面。

数据流（MTR 4.0.5 实测链路）：

```
玩家手持 mtr:brush 右键轨道节点方块（mtr:rail 等）
   ├─ [本模组·客户端] RailNodeInteractionHandler 记录节点坐标（RailScreenBridge）
   │                  —— 不消费事件，右键继续走 MTR 原流程
   └─ [MTR·客户端] BlockNode.onUse2 → MinecraftClientData.getFacingRailAndBlockPos
                     → ClientPacketHelper.openRailShapeModifierScreen(railId)
                          → 打开原版界面 RailModifierScreen（轨道形状/样式，功能完全保留）
                               └─ [本模组] RailModifierScreenMixin @Inject(init2, TAIL)
                                    追加按钮"节点限速判定"
                                      └─ 点击 → NodeModeNetwork.requestOpen(pos)   [C2S]
                                           └─ 服务端回发 node_mode_open（含当前判定）[S2C]
                                                └─ 客户端打开 NodeModeScreen（显示当前判定 + 切换按钮）
                                                     ├─ 点击切换 → toggle 消息 [C2S]
                                                     │    → 服务端 NodeModeStore.toggle 持久化 → 回发 S2C 刷新
                                                     └─ 关闭 → RailScreenBridge.restoreRailScreen()
                                                          → 返回 MTR 原版轨道界面
```

关键实现：

- `client/RailNodeInteractionHandler`（`@Mod.EventBusSubscriber(value = Dist.CLIENT)`）：按**注册表名**匹配
  刷子（`mtr:brush`）与节点方块（`mtr:rail` / `mtr:cable_car_node_*` / `mtr:airplane_node` / `mtr:boat_node`），
  只记录坐标，**不调用 `setUseBlock/setUseItem`**，因此 MTR 原版界面与原版逻辑完全不变。
- `client/RailScreenBridge`：节点坐标（10 分钟有效期）与"返回界面"的持有者。
- `mixin/RailModifierScreenMixin`：
  - `@Mixin(targets = "org.mtr.mod.screen.RailModifierScreen")` —— 用字符串 targets，**不强制加载目标类**；
  - `@Inject(method = "init2", at = @At("TAIL"))` —— MTR 屏幕的控件初始化钩子（`init2` 由 `RailModifierScreen`
    自身声明，4.0.5 发行 jar 已核实存在），在 TAIL 追加按钮；
  - `@Shadow protected abstract void addChild(ClickableWidget)` —— 访问 MTR 映射层基类 `ScreenExtension`
    提供的控件添加方法（4.0.5 jar 中签名 `(Lorg/mtr/mapping/holder/ClickableWidget;)V` 已核实）；
  - 按钮用 MTR 自己的 `ButtonWidgetExtension` + `TextHelper.literal` 创建，位置 `y=50`（原版两行控件在 y=0 / y=25，
    错开避免遮挡）；
  - 点击时先记住当前界面（`Minecraft.getInstance().screen`）再请求服务端开屏。
- `NodeModeNetwork`（Forge `SimpleChannel`）：`node_mode` 通道三条消息 ——
  `RequestOpenNodeModeMessage`（C2S，按钮触发）/ `OpenNodeModeMessage`（S2C，携带坐标与当前判定）/
  `ToggleNodeModeMessage`（C2S，切换并回发）。
- `client/NodeModeScreen`：vanilla `Screen`，切换按钮 + 关闭按钮；`onClose()` 优先返回 MTR 原版轨道界面。
- `NodeModeStore`：`Set<"x,y,z">`，JSON 持久化到 `world/mtrrealrail/nodes.json`；未配置节点取
  `RealRailConfig.defaultNodeMode`（默认 TAIL）。生效点：`SpeedLimitHelper.updateState` 在车头跨越边界时
  查 `NodeModeStore.isTailMode(boundaryPosition)`。

**稳健性设计**：新增的 `mtrrealrail.railgui.mixins.json` 使用 `"required": false` + `"injectors.defaultRequire": 0`
（目标缺失或未来 MTR 改动 `init2` 时只记日志、不影响游戏启动与其他功能）；注入范围为 `client`。

**关键实证（对 4.0.5 发行 jar 用 javap 逐一核对）**：

| 事实 | 核对结果 |
|---|---|
| 刷子右键轨道节点打开的界面 | `BlockNode.class` 引用 `openRailShapeModifierScreen`；`ClientPacketHelper.class` → `org/mtr/mod/screen/RailModifierScreen` ✅ |
