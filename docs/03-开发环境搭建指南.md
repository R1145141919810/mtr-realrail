# 03 · 开发环境搭建指南（从零开始）

目标：在 **MC 1.20.1 + Forge**（Architectury 双平台，同时支持 Fabric）上开发、调试、发布本附属模组（MTR RealRail），兼容 **MTR 4.0.0 及以后版本**。

## 3. 获取项目脚手架

本工作区已提供完整脚手架（`src/` 目录），结构基于 **zbx1425/mtr-addon-template**（MTR 官方维护者之一 zbx1425 维护的附属模组模板，原 jonafanho/MTR-Addon-Template 已删除）：

```
src/
├─ build.gradle            # 根构建：architectury-plugin + loom + setupLibrary
├─ settings.gradle         # include common/fabric/forge
├─ gradle.properties       # 全部版本号（mtr_version、forge、architectury…）
├─ gradle/wrapper/         # Gradle 8.8 wrapper
├─ common/
│  ├─ build.gradle         # 双平台公共代码（编译依赖 checkouts/mtr-common.jar）
│  └─ src/main/
│     ├─ java/mtr/realrail/        # 模组本体（见 02-核心代码实现）
│     └─ resources/mtrrealrail.mixins.json
├─ fabric/                 # Fabric 入口 + fabric.mod.json
└─ forge/                  # Forge 入口 + META-INF/mods.toml
```

若需从零重建：克隆 `https://github.com/zbx1425/mtr-addon-template` 后按本指南改造（该模板是 MTR 3.x 时代的 import 口径，MTR 依赖与包名必须按本指南/文档 01 改为 4.0.x 口径）。

## 4. 首次构建步骤

### 4.1 打开项目并同步
1. IDEA → Open → 选择 `src/` 目录。
2. 首次会提示加载 Gradle 项目，等待同步完成（会自动下载 Minecraft、映射、依赖，**需联网且建议配置代理，见 §7.1**）。

### 4.2 下载 MTR 开发构件（关键一步）
在 IDEA 的 Gradle 面板（或命令行 `gradlew`）运行：

```bash
gradlew setupLibrary
```

该任务从以下地址下载三个 dev jar 到 `checkouts/`：

- `https://storage.zbx1425.cn/mtr-artifacts/libs/<mtr_version>/MTR-common-1.20.1-<mtr_version>-dev.jar`
- `.../MTR-fabric-1.20.1-<mtr_version>-dev-shadow.jar`
- `.../MTR-forge-1.20.1-<mtr_version>-dev-shadow.jar`

> **背景**：MTR 3.x 时代的官方 dev jar 站点 `minecrafttransitrailway.com/libs/` 已不再为 4.0.x 提供该路径（实测 403/404）；NTE 对 1.20.x 改用 zbx1425 维护的镜像 `storage.zbx1425.cn/mtr-artifacts/libs/`（NTE `build.gradle` 中的 `is_1_20` 分支）。`gradle.properties` 中 `mtr_version=latest`，也可改为 `4.0.5` 之类具体版本（取决于镜像目录）。
>
> **备用方案（若镜像不可用）**：直接从 Modrinth 下载发行 jar：
> - Forge：`https://api.modrinth.com/maven/maven/modrinth/minecraft-transit-railway/FORGE-4.0.5+1.20.1/minecraft-transit-railway-FORGE-4.0.5+1.20.1.jar`
> - Fabric：把前缀换成 `FABRIC-4.0.5+1.20.1`
>
> 将 Forge 版 jar 重命名为 `checkouts/mtr-common.jar`（`org.mtr.core.*` 类在其内部，编译期只用到它们；fabric/forge 运行用 jar 则分别拷贝到对应 `run/mods/`，或改用 §4.3 的 Modrinth Maven 依赖写法）。

### 4.3 运行库就位
```bash
gradlew setupRunMods
```
把 `mtr-fabric.jar` / `mtr-forge.jar` 拷贝到 `fabric/run/mods/`、`forge/run/mods/`。

> 另一种更现代的写法（JCM 生产环境采用）：在 `forge/build.gradle` 中直接
> ```groovy
> repositories {
>     exclusiveContent {
>         forRepository { maven { name = "Modrinth"; url = "https://api.modrinth.com/maven" } }
>         forRepositories(fg.repository)
>         filter { includeGroup "maven.modrinth" }
>     }
> }
> dependencies {
>     implementation fg.deobf("maven.modrinth:minecraft-transit-railway:FORGE-4.0.5+1.20.1")
> }
> ```
> Fabric 对应 `modImplementation "maven.modrinth:minecraft-transit-railway:FABRIC-4.0.5+1.20.1"`。
> 此方式不依赖镜像，推荐用于长期维护；本脚手架的 common 模块仍需 `mtr-common.jar` 编译核心类。

### 4.4 再次同步并构建
```bash
gradlew build          # 或 gradlew :forge:build / gradlew :fabric:build
```
产物位于 `forge/build/libs/mtrrealrail-1.20.1-0.1.0.jar`（remapJar 后为最终可分发 jar）。

## 5. 运行与调试

- IDEA → Gradle 面板 → `forge/Tasks/forgegradle runs` → **runClient**（单机客户端）或 **runServer**（专用服务端）。
- 客户端测试：MTR 需要资源包与存档；新建世界后放置轨道、轨道连接器、信号连接器、侧线（Siding）、车库（Depot）并刷车（与 MTR 正常玩法一致）。
- 服务端逻辑调试：本模组的速度判定与信号隔离全部在**服务端**完成（MTR 4.0.x 的列车仿真由服务端 TSC `Simulator` 驱动，客户端仅同步），因此 runServer + 断点即可覆盖核心逻辑；GUI 部分需要 runClient。
- Mixin 调试技巧：运行参数加 `-Dmixin.debug.verbose=true -Dmixin.debug.export=true`，日志中查看 `Mixin apply for mod mtrrealrail ... SUCCESS`；导出反混淆源码至 `.mixin.out/` 便于核对注入点。

## 6. 验证清单（游戏内）

| 功能 | 操作 | 预期 |
|---|---|---|
| 需求一：车尾判定 | 铺设两段限速不同的轨道（如 120 → 40 连接器），观察列车 | 车头进入新段时速度不变，**车尾完全通过连接器后**才开始加减速 |
| 节点单独切换 | 手持刷子（mtr:brush）右击轨道节点方块（mtr:rail） | 先打开 **MTR 原版轨道界面**（轨道形状 / 轨道样式，原版功能不变）；界面内新增"节点限速判定"按钮 → 点击进入判定界面 → 切换后关闭自动返回原界面；设置持久化（`world/mtrrealrail/nodes.json`） |
| 需求二：信号隔离 | 同一段轨道放 A、B 两色信号连接器与各自信号灯；A 系统前方停一列车 | A 系统红灯只拦"属于 A 系统"的列车；B 系统区间状态不受 A 系统列车影响 |
| 回归 | 平台停车、折返、红灯急停、手动驾驶 | 均正常（安全制动逻辑未被改动） |

## 7. 常见问题

### 7.1 网络/下载
- 国内环境建议为 Gradle 配置镜像（`~/.gradle/gradle.properties` 添加阿里云镜像仓库），并确保能访问 `maven.fabricmc.net`、`maven.architectury.dev`、`maven.minecraftforge.net`、`maven.parchmentmc.org`、`api.modrinth.com`。
- Mojang 官方映射/客户端资源下载较慢属正常现象，耐心等待或使用代理。

### 7.2 同步失败
- 确认 JDK 17 被 IDEA 选中（Project SDK）。
- 删除 `.gradle/`、`build/` 后重新同步。
- `setupLibrary` 404：镜像路径或版本目录不存在 → 改 `mtr_version` 或用 §4.3 的 Modrinth Maven 方案。

### 7.3 Mixin 未生效 / 崩溃
- 确认 `mtrrealrail.mixins.json` 在 fabric.mod.json 的 `mixins` 数组与 forge 的 `loom.forge.mixinConfig` 中都正确声明（脚手架已配好）。
- 若 MTR 升级（如 4.0.6+）导致 `@Redirect` 找不到调用点，日志会报 `Critical injection failure`；此时按文档 01 的"改动点对照表"核对目标方法字节码（用 IDEA 反编译发行 jar），并按文档 04 的适配指引更新 mixin。

### 7.4 多版本/多平台
- 本脚手架为单版本（1.20.1）精简版；若需多 MC 版本，参考 NTE 的 Manifold 预处理方案（`zbx1425/mtr-nte`）。
- 若目标改为 NeoForge/MC 1.21，需升级 architectury 版本并重验 mixin 目标（MTR 对应版本线为 `NEOFORGE-4.x`）。
