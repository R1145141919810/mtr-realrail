## 2. 与 docs/03 的差异：构建工具链

docs/03 指定 Architectury 脚手架，但脚手架中的两个插件版本**已从 maven.architectury.dev 下架**：

```
dev.architectury.loom:dev.architectury.loom.gradle.plugin  → 无 1.0-SNAPSHOT
architectury-plugin:architectury-plugin.gradle.plugin      → 无 3.4-SNAPSHOT
```

（均为查询 maven-metadata.xml 实测结果，只有 3.5-SNAPSHOT / 1.3.358 / 1.0.311 等具体版本与更新的快照。）

因此改为 **ForgeGradle 6.0.54 + Forge 1.20.1-47.4.23 + 官方映射 1.20.1**（与 docs/03 的
"MC 1.20.1 / Forge 47.x / JDK 17 / Gradle wrapper" 版本矩阵一致，仅把构建插件从 arch-loom 换成 ForgeGradle），
并把 Architectury API 替换为等价的 Forge 原生 API：

| docs/02 中的 Architectury API | 交付实现（Forge 原生） |
|---|---|
| `dev.architectury.networking.NetworkManager` | `net.minecraftforge.network.SimpleChannel`（`NodeModeNetwork`） |
| `PlayerEvent.INTERACT_BLOCK` | `PlayerInteractEvent.RightClickBlock`（`RailNodeInteractionHandler`） |
| `LifecycleEvent.SERVER_STARTED` | `ServerStartedEvent`（`MtrRealRail#onServerStarted`） |
| `@Environment(Env.CLIENT)` 剥离 | 客户端类集中到 `mtr.realrail.client` 包，S2C 处理经 `DistExecutor` 隔离 |

这样产出的 Forge jar **不依赖 Architectury API**，只需 Forge + MTR 即可运行。

## 3. 编译依赖：必须使用 MTR **发行 jar**（而不是 dev jar）

MTR 4.0.x 发行 jar 把 fastutil **重定位**到了 `org.mtr.libraries.it.unimi.dsi.fastutil.*`
（实测：`org/mtr/libraries/it/unimi/dsi/fastutil/objects/ObjectList.class` 等 1306 个类）。
Mixin 的注入描述符必须与运行时字节码一致，因此本模组按**发行 jar**编译：

```
gradlew setupLibrary
```

该任务会：

1. 若工作区已有发行 jar（`checkouts/mtr-forge-<版本>.jar` 或 `../checkouts/mtr-forge-release.jar`）则直接复用；
2. 否则从 Modrinth Maven 下载
   `https://api.modrinth.com/maven/maven/modrinth/minecraft-transit-railway/FORGE-4.0.5+1.20.1/minecraft-transit-railway-FORGE-4.0.5+1.20.1.jar`
   （下载后校验 zip 完整性，失败重试 3 次）；
3. 裁剪出 `libs/mtr-compile.jar`（`org/mtr/core/**` + `org/mtr/libraries/it/**`）作为 **compileOnly** 依赖。

## 4. 源码实证修正清单（相对 docs/01、docs/02）

以下问题都是**用 javap 核对发行 jar 字节码 + 在真实 Forge 1.20.1 服务端实跑**发现的，
按 docs/02 原样编写会在运行期失败：

| # | docs/02 原写法 | 实证结果 | 修正 |
|---|---|---|---|
| 1 | `target = "...Siding;getUpcomingSlowerSpeed(...ObjectList;IDD)D"` | 发行 jar 调用点描述符为 `(ObjectList;IDDD)D`（ObjectList + int + **3** 个 double）：`412: invokestatic org/mtr/core/data/Siding.getUpcomingSlowerSpeed:(Lorg/mtr/libraries/it/unimi/dsi/fastutil/objects/ObjectList;IDDD)D` | 描述符补一个 `D`。少写只会得到 `failed injection check, (0/1) succeeded`，Mixin **不会**提示"描述符不匹配"，极易误判 |
| 2 | `@Shadow private double railProgress;`（mixin 目标 Vehicle） | `railProgress` 声明在**父类** `org.mtr.core.generated.data.VehicleSchema`；Mixin 的 `@Shadow` 只在目标类自身字段中查找 → 报 `@Shadow field railProgress was not located in the target class org.mtr.core.data.Vehicle` | 新增 `VehicleSchemaAccessor`：`@Mixin(VehicleSchema.class)` + `@Accessor("railProgress")`，通过 `((VehicleSchemaAccessor) (Object) vehicle)` 访问 |
| 3 | （未提及） | Mixin 0.8.5 要求 Redirect **handler 的 static 修饰符与被注入方法一致**（`simulateMoving` 是实例方法）→ handler 写成 `static` 会报 `'static' modifier of handler method does not match target` | `mtrrealrail$getUpcomingSlowerSpeed` 用实例方法 |
| 4 | （未提及） | 阴影字段同时写 `@Final` 注解与 Java `final` 修饰符，会触发 4 条 `@Final field ... should be final` 警告 | 只保留 `@Final` 注解，去掉 Java `final` |
| 5 | 交互按方块名 `mtr:rail_connector*` 匹配 | 实测 MTR 4.0.5：**轨道连接器是物品**（`item.mtr.rail_connector_20…300`，含 `_one_way` 变体），节点**方块**是 `mtr:rail`（另有 `cable_car_node_*`/`airplane_node`/`boat_node`） | 交互判定改为：手持 `mtr:brush` + 目标方块属于节点方块集合 |
| 6 | 类名 `NodeModePackets` / `RailConnectorInteractionHandler` | 语义上不再是"包(packet)注册表"而是 Forge 通道，且交互目标是轨道节点方块 | 重命名为 `NodeModeNetwork` / `RailNodeInteractionHandler` |

其余已核对无误的关键签名（javap 逐一确认）：`Vehicle.simulate(long, ObjectArrayList, Long2LongAVLTreeMap)`、
`Vehicle.simulateMoving(long, ObjectArrayList, int)`（其中 `getSpeedLimitMetersPerMillisecond()` 与
`getUpcomingSlowerSpeed` 各只出现一次）、`Rail.isBlocked(long, BlockReservation)`（包级私有）、
`Rail.reserveRail(long, long, ObjectOpenHashSet, Rail, boolean)`（私有静态）、Rail 的四张
`Long2LongAVLTreeMap` 预留表、`PathData.getOrderedPosition1()/getSignalColors()/getStartDistance()/getEndDistance()`、
`Position.getX/Y/Z()` 返回 `long`、`Utilities.getElement/getIndexFromConditionalList`。

### 5.3 开发环境（ForgeGradle）的注意事项

ForgeGradle 开发环境中模组以"目录"（`build/classes` + `build/resources`）形式加载，**没有 MANIFEST**，
而 Forge 是通过 `MixinConfigs` 清单属性注册 Mixin 配置的，因此在开发环境里：

* Mixin **不会生效**（现象：目标类能加载、日志里没有 `Mixing ...` 行）；
* 生产版 MTR jar 放在 `run/mods` 也**无法**在开发环境加载（MTR 自带 mixin 使用 SRG 名，开发环境为官方名）。

因此：
1. **功能/集成验证请在真实 Forge 客户端或服务端里、把 jar 放进 `mods/` 进行**（本次交付即如此验证）；
2. 若只想让 `runServer` 能起来，可先执行 `gradlew buildMtrStubJar`，它会生成
   `run/mods/mtr-stub.jar`（内含裁剪后的 `org.mtr.core` 类，仅占位，供开发环境加载）。

## 6. 构建与运行

```bash
cd src
gradlew setupLibrary      # 下载/复用 MTR 发行 jar，生成 libs/mtr-compile.jar
gradlew build             # 产物 build/libs/mtrrealrail-1.0.0+1.20.1.jar
gradlew buildMtrStubJar   # 可选：生成开发环境用的 run/mods/mtr-stub.jar
gradlew runServer         # 开发环境服务端（需上面的 stub）
```

部署：把 `mtrrealrail-1.0.0+1.20.1.jar` 与 MTR 本体一起放进 `mods/` 即可（客户端/服务端均可）。

## 7. 需求对照

| 需求 | 实现位置 | 说明 |
|---|---|---|
| 一、车尾完全经过连接器后才变速 | `SpeedLimitHelper#updateState/getEffectiveSpeedLimit` + `VehicleSimulateMixin` 的两个注入点 | 车头跨界 → 记录 pending（保持旧段限速）；车尾越过 → 生效；预制动同步改为"车尾感知"（扫描到 TAIL 节点即停止） |
| 一、按节点切换车头/车尾判定 | `NodeModeStore`（`world/mtrrealrail/nodes.json`）+ `RealRailConfig.default_node_mode` | 刷子右击节点方块 → **MTR 原版轨道界面照常打开**（界面内新增"节点限速判定"按钮，见 `RailModifierScreenMixin`）→ 点击按钮请求开屏 → 点击切换 → 立即持久化，关闭后返回原版界面 |
| 二、多信号系统互不干扰 | `SignalIsolationRegistry` + `VehicleSimulateMixin` 登记 + `RailSignalIsolationMixin` 过滤 | 每 tick 计算车身覆盖段 `signalColors` 并集；`Rail.isBlocked` 只检查/预留该颜色集合；未登记回退原版 |
| 安全制动/防撞不受影响 | 未注入 stoppingPoint 分支与 `VehiclePosition` 重叠检测 | 信号红灯、平台停车、前方占用仍立即生效 |
